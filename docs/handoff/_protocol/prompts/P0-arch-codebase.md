## 步骤

1. **实测命令**。安装、dev、build、typecheck、test、bench（有什么跑什么），记下**真实命令、真实输出、耗时**。测试要记：总数、通过数、耗时、已知 flaky。**命令如果静默通过、没有测试数量输出，就写「无测试」**，不要写成「通过」。
2. **模块地图**：目录 → 职责 → 对外入口（index / 公开导出）。标出哪些是"核心"、哪些是"边缘/适配器"。
3. **依赖关系**（用 `rg` 抓 import / use / require）：列出跨层、跨包、跨模块的引用；标出**循环依赖嫌疑**，每条给证据（`a.ts:12 → b.ts`）。
4. **运行时拓扑**：进程 / 服务 / 队列 / DB / 外部 API / 定时任务。**多实例相关**重点标：进程内可变状态、内存缓存、本地文件、定时任务、锁、幂等性——每条给证据。
5. **现有约定**（从代码反推，不写建议）：错误处理、日志、配置、依赖注入、测试风格、命名。
6. **风险候选 ≤10 条**：每条带 `file:line` 证据 + 一句话后果（例：`api/order.ts:88` 用内存 Map 做幂等，多实例下失效）。
7. 按 `docs/handoff/_protocol/templates/CODEBASE.md` 写文件。

## 硬性要求

- 每条结论必须带证据（文件:行号 或 命令输出）。没有证据的写"未验证"。
- **不做设计决策、不提改进方案、不改任何代码**——方案是 Opus 的事。
- 总长 ≤250 行。超了说明在抄代码。
- 单列「给 Opus 的 3 个必须由人 / Opus 决定的问题」。
